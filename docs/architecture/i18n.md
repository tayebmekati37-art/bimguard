# Japanese language support (Milestone 18)

## What is translated

Two languages are supported in the frontend: **English** (default) and
**Japanese**. The dictionary lives in `apps/web/src/lib/i18n.ts`. The
language switcher sits in the header and updates the page without a
reload. On first visit the browser's `Accept-Language` decides: a `ja`
preference starts in Japanese, anything else starts in English. The
choice persists in `localStorage` under `bimguard.locale`.

Keys that ARE translated (~50):

| Group | Examples |
| :--- | :--- |
| Navigation | Dashboard, Projects, Rules, Settings, Audit, Notifications, Sign out |
| Roles | Admin, BIM coordinator, Engineer, Reviewer, Viewer |
| Health states | Healthy, Warning, Stale, Critical |
| Readiness | Ready for issue, Ready with warnings, Not ready for issue, Not yet validated |
| Severities | Critical, High, Medium, Low |
| Revision statuses | Draft, In review, Approved, Issued, Superseded, Rejected |
| Disciplines | Architecture, Structure, MEP, Equipment, Quantity, General |
| Common actions | Save, Cancel, Delete, Edit, Add, Run, Refresh, Validate, Download, Confirm |

## What is NOT translated

Page body text, help text, form field labels, validation error messages
from the backend, and the content of `docs/` (that has separate
Japanese and English pages).

Specifically, the following still show English in their bodies:

- Login form labels
- Project page (`/projects/[id]`) — every section below the header
- Validation, impact, dependency, reports, ask, audit, notifications — page bodies

The header is translated and switches language live. The rest of the UI
is pending review by a Japanese-speaking BIM engineer, which is not
available in this environment.

## Japanese terminology notes

Terms chosen for technical accuracy, not for literal translation:

- **Stale** → 要確認 ("requires confirmation") — chosen over 古い ("old")
  because the state is about review status, not age.
- **MEP** → 設備 ("facilities/equipment services") — standard for the
  MEP discipline in Japanese construction documents.
- **Superseded** → 失効 ("lapsed/invalidated") — standard in document
  management, not the literal translation 置き換え ("replaced").
- **Readiness** → 発行可否 ("issuable or not") rather than the literal
  準備完了, to match how these documents are actually signed off.
- **Issue** (as a verb, "issue a drawing") → 発行. **Issue** (as a noun,
  "a validation finding") → 課題. The two are kept distinct.

These should be reviewed by someone with BIM/CIM domain experience before
being used in a customer-facing demo. `docs/architecture/i18n.md` (this
file) is the record of what has been reviewed and what has not.

## How to add a translation

1. Add the key and English value under `DICTS.en` in `i18n.ts`.
2. Add the Japanese value under `DICTS.ja`.
3. Use it in a client component via `const { t } = useT(); t("your.key")`.
4. Run the parity check: from `apps/web`, `npx tsx src/lib/i18n.test.ts`.
   It fails if any key is missing in a non-English locale, or has an
   empty value.
5. Do not add a Japanese translation without a Japanese-speaking reviewer
   confirming the domain meaning. Machine-translated strings that change
   engineering meaning are worse than English-only.
